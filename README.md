# JMeter Terraform Module

Terraform module for provisioning a private, distributed Apache JMeter environment on Oracle Cloud Infrastructure.

The module creates one JMeter controller, a configurable number of JMeter workers, the network security groups needed for JMeter RMI traffic, optional private networking, optional OCI Bastion access, and optional Object Storage resources used to host JMeter binaries and test packages.

## What It Creates

Depending on the provided variables, the module can create:

- A private VCN, subnet, NAT Gateway, Service Gateway, and route table.
- Or, it can reuse an existing VCN or an existing private subnet.
- A JMeter controller compute instance.
- One or more JMeter worker compute instances.
- Controller and worker SSH key pairs generated by Terraform.
- Network Security Groups for controller and workers.
- Optional OCI Bastion for SSH access to private nodes.
- Optional Object Storage bucket for JMeter resources.
- Optional Object Storage object containing the JMeter binary archive.
- Optional bucket-level PAR for reading, writing, and listing JMeter resources.

## Architecture

The controller runs JMeter client commands and coordinates remote workers through JMeter RMI.

Workers run `jmeter-server` as a systemd service. They are placed in a private subnet and receive the controller public key plus the workers public key, allowing the controller to distribute test packages to all configured remotes.

The controller receives helper scripts through cloud-init:

- `jmeter-test`: runs a JMeter test plan and uploads session bundles when a PAR URL is configured.
- `jmeter-package-get`: downloads a package archive from Object Storage, extracts it locally, copies the same archive to workers, and extracts it there.
- `jmeter-package-list`: lists package archives available in Object Storage.

Cloud-init user data is compressed with `base64gzip` to stay below OCI instance metadata size limits.

## Requirements

- Terraform `>= 1.4.0`
- OCI Terraform provider `>= 6.2.0`
- External provider `>= 2.3.0`
- OCI provider authentication through an OCI CLI config profile, explicit API key variables, or supported OCI provider environment variables
- Internet access from Terraform if automatic JMeter binary download is enabled
- Private subnet egress through a NAT Gateway or equivalent route if nodes download JMeter directly from Apache mirrors

The module can use an OCI CLI config profile:

```hcl
region                  = "<oci-region>"
tenancy_ocid            = "ocid1.tenancy..."
oci_config_file_profile = "DEFAULT"
```

Or explicit API key variables:

```hcl
region                   = "<oci-region>"
tenancy_ocid             = "ocid1.tenancy..."
current_user_ocid        = "ocid1.user..."
oci_api_key_fingerprint  = "<api-key-fingerprint>"
oci_api_private_key_path = "~/.oci/oci_api_key.pem"
```

`tenancy_ocid` and `region` are always module inputs because they are used by tenancy-scoped data sources. When `oci_config_file_profile` is set, the provider uses that profile for authentication and does not require the explicit API key variables. `current_user_ocid`, `oci_api_key_fingerprint`, and `oci_api_private_key_path` are only required when configuring the provider through explicit API key variables.

## Network Modes

### Create A New Network

If neither `nodes_vcn_id` nor `nodes_subnet_id` is provided, the module creates:

- VCN
- private subnet
- NAT Gateway
- Service Gateway
- default route table rules

The network is created in `network_compartment_id` when set, otherwise in `nodes_compartment_id`.

### Reuse An Existing VCN

Set `nodes_vcn_id` and leave `nodes_subnet_id` empty.

The module creates a private subnet in the selected VCN. The VCN compartment is inferred from the VCN data source unless `network_compartment_id` is set.

### Reuse An Existing Subnet

Set `nodes_subnet_id`.

The module infers:

- subnet CIDR
- VCN ID
- network compartment

In this mode, `nodes_vcn_id` and `nodes_subnet_cidr` are not required for node placement.

## Security Groups

The module creates separate NSGs for controller and workers.

### Worker NSG

Allows inbound JMeter worker RMI traffic from the nodes subnet CIDR:

- TCP `jmeter_port`
- default: `1099`

### Controller NSG

Allows inbound JMeter controller RMI callback traffic from the nodes subnet CIDR:

- TCP `jmeter_client_port` through `jmeter_client_port + 2`
- default: `4000-4002`

## Bastion

OCI Bastion creation is controlled by:

```hcl
create_bastion = true
```

By default, the bastion is created in the network compartment. Override with:

```hcl
bastion_compartment_id = "ocid1.compartment..."
```

The bastion targets the JMeter subnet and uses `bastion_allowed_cidr_blocks` for client source filtering.

## Object Storage Resources

Set the following variable to let the module manage JMeter resources in Object Storage:

```hcl
upload_jmeter_resources_to_object_storage = true
```

When enabled, the module:

- creates an Object Storage bucket
- downloads the configured Apache JMeter archive locally if no local archive path is provided
- uploads the archive as an object under `binaries/`
- creates a bucket-level PAR

The JMeter binary object name is fixed:

```text
binaries/apache-jmeter-<jmeter_version>.tgz
```

This fixed layout is important because cloud-init downloads:

```text
<effective_jmeter_resources_url>/apache-jmeter-<jmeter_version>.tgz
```

When the module creates Object Storage resources, `effective_jmeter_resources_url` resolves to:

```text
<jmeter_resources_par_url>/binaries
```

### PAR Access

The generated PAR defaults to:

```hcl
access_type           = "AnyObjectReadWrite"
bucket_listing_action = "ListObjects"
```

This allows:

- downloading JMeter binaries
- downloading test packages
- uploading test packages
- uploading result bundles
- listing available packages

The PAR URL is taken from the OCI provider-computed `full_path` and normalized by removing the trailing slash.

If `upload_jmeter_resources_to_object_storage = false`, the local PAR URL falls back to the user-provided `jmeter_resources_par_url`.

## Test Package Layout

Packages are expected to be `.tar.gz` archives stored under:

```text
packages/<package-name>.tar.gz
```

When extracted on the controller or workers, package contents are placed under:

```text
/home/opc/performance
```

Typical package layout:

```text
config/
  env.<name>.properties
plans/
  <test-plan>.jmx
resources/
  dataset/
```

## Controller Helper Commands

After provisioning, connect to the controller as `opc`.

### List Packages

```bash
jmeter-package-list
```

or with an explicit PAR URL:

```bash
jmeter-package-list -u '<par-url>'
```

### Download And Install A Package

```bash
jmeter-package-get -n <package-name>
```

Use `-f` to overwrite existing local files:

```bash
jmeter-package-get -f -n <package-name>
```

The command installs the package on the controller. If `remote_hosts` are configured, it also copies the archive to every JMeter worker and extracts it there.

### Run A Test

```bash
jmeter-test -e <environment> -p <test-plan> -u 10 -t 300
```

Common options:

- `-e`: environment name, loading `/home/opc/performance/config/env.<name>.properties`
- `-p`: test plan name, loading `/home/opc/performance/plans/<name>.jmx`
- `-u`: number of concurrent users
- `-i`: ramp-up time in seconds
- `-t`: running time in seconds
- `-c`: constant delay in milliseconds
- `-d`: random delay in milliseconds
- `-s`: include sub-samples in results
- `-l`: disable distributed remote mode even when workers are configured

When remote mode is enabled, the script adds `-r` and divides the requested user count by the number of configured remotes, with a minimum of one user per remote.

Results are written under:

```text
/home/opc/performance/sessions/<session-id>
```

Session bundles are written under:

```text
/home/opc/performance/bundles
```

If a PAR URL is configured, session bundles are uploaded to:

```text
<jmeter_resources_par_url>/bundles/<session-id>.tar.gz
```

## Example Configuration

Create network, nodes, bastion, and Object Storage resources:

```hcl
region                  = "<oci-region>"
tenancy_ocid            = "ocid1.tenancy..."
oci_config_file_profile = "DEFAULT"

nodes_compartment_id = "ocid1.compartment..."

workers_count = 2
nodes_shape   = "VM.Standard.E5.Flex"
nodes_ocpus   = 1
nodes_memory  = 32

create_bastion = true

upload_jmeter_resources_to_object_storage = true
jmeter_resources_bucket_name              = "jmeter-resources"
```

Reuse an existing private subnet:

```hcl
region                  = "<oci-region>"
tenancy_ocid            = "ocid1.tenancy..."
oci_config_file_profile = "DEFAULT"

nodes_compartment_id = "ocid1.compartment..."
nodes_subnet_id      = "ocid1.subnet..."

upload_jmeter_resources_to_object_storage = true
```

Use an existing Object Storage PAR instead of creating Object Storage resources:

```hcl
upload_jmeter_resources_to_object_storage = false
jmeter_resources_par_url                  = "https://objectstorage..."
jmeter_resources_url                      = "https://downloads.apache.org/jmeter/binaries"
```

In this mode, nodes download JMeter binaries directly from `jmeter_resources_url`.

## Outputs

### `jmeter`

Contains:

- `nodes.bastion_id`
- `nodes.controller`
- `nodes.workers`
- `object_storage.jmeter_binaries_object_name`
- `object_storage.jmeter_resources_bucket_name`
- `object_storage.jmeter_resources_par_url`

Example:

```bash
terraform output -json jmeter
```

### `security`

Sensitive output containing generated SSH key pairs:

- `key_pairs.controller.private_key`
- `key_pairs.controller.public_key`
- `key_pairs.workers.private_key`
- `key_pairs.workers.public_key`

Example:

```bash
terraform output -json security
```

Handle this output carefully. It contains private SSH keys.

## Apply Workflow

```bash
terraform init
terraform validate
terraform plan
terraform apply
```

After apply, get the controller private IP and optional bastion OCID:

```bash
terraform output -json jmeter
```

If the generated PAR changes, run `terraform apply` or `terraform apply -refresh-only` before relying on `terraform output`, because root outputs are stored in Terraform state and are recalculated during apply.

## Operational Notes

- Adding or changing immutable PAR fields such as `access_type`, `bucket_listing_action`, or `time_expires` can force PAR replacement.
- Replacing a PAR creates a new URL token. Any instance metadata or external tooling that uses the old URL must be refreshed or updated.
- The generated PAR includes `bucket_listing_action = "ListObjects"`. A lifecycle rule ignores changes to that field to avoid repeated drift if the provider/API does not read it back consistently.
- If `upload_jmeter_resources_to_object_storage` is enabled and `jmeter_resources_local_path` is unset, Terraform downloads the Apache JMeter archive locally before uploading it.
- The generated bucket uses `NoPublicAccess`.
- The JMeter archive object is uploaded with the `InfrequentAccess` storage tier.
- Controller and worker instances are private. Use OCI Bastion or another private access path to connect.
